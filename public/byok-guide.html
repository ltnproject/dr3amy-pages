Bring your own API key

Rigel's Work (Code) tab runs on free, shared Groq models. When both the primary model (openai/gpt-oss-120b) and its backup (llama-3.3-70b-versatile) are unavailable — usually a rate limit during busy periods — Rigel will say so and link here. This page shows you how to get your own key from a few providers and wire it into your own copy of the proxy Worker, so you're never blocked by shared capacity.

1. Get a key

Pick whichever provider you already use, or whichever is cheapest for your usage. Any one of these is enough.

ChatGPT API

OpenAI
  1. Sign in at platform.openai.com
  2. Open API keys, create a new secret key
  3. Add billing — the API is pay-as-you-go, separate from a ChatGPT Plus subscription
platform.openai.com/api-keys →

Claude API

Anthropic
  1. Sign in at console.anthropic.com
  2. Open API Keys, create a key
  3. Add credit under Billing to activate it
console.anthropic.com/settings/keys →

OpenRouter

Multi-model router
  1. Sign in at openrouter.ai
  2. Open Keys, create a key
  3. One key gives you access to dozens of models, including free-tier ones
openrouter.ai/keys →

Google AI Studio

Gemini
  1. Sign in at aistudio.google.com
  2. Open Get API key, create a key
  3. Has a free tier with daily rate limits
aistudio.google.com/app/apikey →

Gemini's API expects the key as a query parameter or an x-goog-api-key header, not a Bearer token — see the note below.

2. Wire it into your own Worker

Fork the repo, deploy a second small Worker with your key as a secret, then point the widget at it. Never put a key directly in client-side code.

  1. In your fork, copy worker-ai.js to e.g. worker-byok.js and set UPSTREAM_URL to your provider's chat-completions endpoint.
  2. Deploy it with its own wrangler.toml and store your key as a secret — never hardcode it: 
    wrangler secret put API_KEY --config wrangler-byok.toml
  3. Point RIGEL_CODE_API in rigel-widget.js at your new Worker's URL.
// minimal proxy shape — same pattern as the site's existing worker.js
const ALLOWED_ORIGIN = "https://dr3amy.creepers.pro";

export default {
  async fetch(request, env) {
    // ...origin / referer checks, same as worker-ai.js...

    const response = await fetch(env.UPSTREAM_URL, {
      method: "POST",
      headers: {
        "Authorization": `Bearer ${env.API_KEY}`,
        "Content-Type": "application/json"
      },
      body: await request.text()
    });

    return new Response(response.body, {
      status: response.status,
      headers: {
        "Content-Type": response.headers.get("Content-Type") || "application/json",
        "Access-Control-Allow-Origin": ALLOWED_ORIGIN,
        "Vary": "Origin"
      }
    });
  }
};
Google AI Studio is the exception. Gemini's REST API doesn't take an Authorization: Bearer header — it wants the key as ?key=... on the URL or an x-goog-api-key header, and the request/response shape differs from the OpenAI-style format Groq, OpenAI and OpenRouter share. If you pick Gemini, adjust the fetch call accordingly rather than reusing the template above as-is.
